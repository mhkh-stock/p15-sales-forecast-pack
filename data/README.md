# P15 — Data dictionary + known quirks

## The sales file — `data/raw/monthly_sales_SAMPLE.csv`

SAMPLE monthly sales file for the fictional shop **Noor Electronics,
Lahore**, Jan 2024 – Oct 2025 (22 months). PKR 68,170,300 total,
3,098,650 a month on average. Generated by `src/generate_data.py`
(seed 20261111) from a base level, a +1.5%/month growth trend and a
Pakistani electronics seasonality (Ramadan/Eid peaks, summer cooling
peak, wedding-season lift, winter dip), with ±4% noise per month.

| Column | Type | Meaning |
|---|---|---|
| month | text | `Jan 2024` … `Oct 2025`; the file's key — must be unique |
| year | integer | 2024 or 2025 |
| month_no | integer | 1–12 (calendar month, drives the seasonal index) |
| sales_pkr | integer (PKR) | Total sales in the month; rounded to the nearest 100 |
| orders | integer | Orders in the month; total / avg ticket (~PKR 14,500) |
| units | integer | Units sold; sum of category units (category sales / avg ticket) |
| mobiles_pkr | integer (PKR) | Mobiles & Tablets sales — must sum with the other 4 categories to sales_pkr |
| tvs_audio_pkr | integer (PKR) | TVs & Audio sales |
| home_appliances_pkr | integer (PKR) | Home Appliances sales |
| fans_cooling_pkr | integer (PKR) | Fans & Cooling sales — share rises May–Aug, falls Dec–Feb |
| accessories_pkr | integer (PKR) | Accessories sales |
| notes | text | Season flag (Ramadan/Eid, wedding season, winter dip) or blank |

## The forecast — `data/processed/forecast.csv`

One row per forecast month (6 rows), computed by `src/forecast.py`:

| Column | Type | Meaning |
|---|---|---|
| month | text | `Nov 2025` … `Apr 2026` |
| year / month_no / t | integer | Calendar month; t = time index (Jan 2024 = 0, so Nov 2025 = 22) |
| seasonal_index | float | Calendar-month index from the shop's own history (12 indices average 1.0) |
| trend_pkr | integer (PKR) | OLS trend value at t (intercept + slope × t) |
| forecast_pkr | integer (PKR) | trend × seasonal index, rounded to the rupee |
| share_pct | float | Forecast month's share of the 6-month total |

## The backtest — `data/processed/backtest.csv`

One row per hold-out month (3 rows: Aug–Oct 2025). The model was
re-fitted on Jan 2024 – Jul 2025 only, so these months were unseen:

| Column | Type | Meaning |
|---|---|---|
| month / t / month_no | — | As in the forecast file |
| actual_pkr | integer (PKR) | What the shop actually sold |
| forecast_pkr | integer (PKR) | What the backtest model forecast |
| error_pkr | integer (PKR) | forecast − actual (negative = under-forecast) |
| ape_pct | float | Absolute percentage error for the month |

## The seasonal indices — `data/processed/seasonal_indices.csv`

One row per calendar month (12 rows): the index from the full 22-month
fit and from the 19-month backtest fit. Both sets average exactly 1.0.

## The forecast summary — `outputs/forecast_summary.json`

Machine-readable summary: headline KPIs, trend parameters, the 12
seasonal indices, the 6 forecast months, the backtest (months + MAPE).

## The database — `data/processed/sales.db`

SQLite, star-lite: `dim_month` (22 rows), `dim_category` (5 rows),
`fact_monthly_sales` (110 rows = 22 × 5), `fact_monthly_totals`
(22 rows), `fact_forecast` (6 rows). Rebuildable from the pushed
scripts and CSVs (`python3 src/build_sqlite.py`) and intentionally
NOT uploaded to GitHub.

## Known quirks (kept, flagged, never silently edited)

- **Nov and Dec indices rest on one observation each** — the file has
  only one Nov (2024) and one Dec (2024). They are the best estimate
  from this file and will steady as more months arrive; re-run the
  forecast every month.
- **The trend is a straight line.** It cannot see a new competitor,
  a price change or a supply shock — if the shop changes, the
  forecast must be re-run, not defended.
- **The backtest is 3 months.** A 3-month MAPE (4.82%) is an honest
  signal, not a guarantee — the What-If sheet exists to stress-test
  slower growth.
- **Category units are derived, not counted.** Units per category are
  category sales divided by a fixed average ticket (Mobiles PKR 42,000;
  TVs PKR 65,000; Home Appliances PKR 28,000; Fans PKR 9,500;
  Accessories PKR 2,800), so they are approximate by construction.
- `data/processed/sales.db` is rebuildable from the pushed scripts
  and CSVs (`python3 src/build_sqlite.py`) and is intentionally NOT
  uploaded to GitHub.
